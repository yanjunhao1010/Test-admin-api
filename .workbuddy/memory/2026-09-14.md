# 2026-09-14

## FastAPI 项目改造：支持部署到阿里云 ECS

目标形态：阿里云 ECS（Alibaba Cloud Linux 3.2104）+ RDS MySQL 8.0 + 公网 IP 直连 HTTP + systemd 托管 Gunicorn。

### 修复的部署阻塞问题
- **硬编码 Windows 路径** `D:\pyproject\Fast_api_project\src\config\config.yml` → 改为基于 `__file__` 推导的 `CONFIG_PATH`（写法对齐既有的 `src/routers/rbac.py:31-34`）：
  - `src/routers/testcases.py`、`src/routers/users.py`、`src/routers/taskcases.py`、`src/routers/uploadfiles.py`
  - 不改的话这 4 个路由在 Linux 上一调用就抛 `FileNotFoundError`
- **src/main.py 重写**：
  - `_load_env()` 提到 `from routers import ...` 之前。原来 `AIS.py:217` 在模块导入期就读 `DEEPSEEK_API_KEY` 构造 OpenAI 客户端，而 `_load_env()` 在 main.py 第 28 行才执行 → 服务器上 AI 接口固定返回 500「服务端未配置 DEEPSEEK_API_KEY」。本地不暴露是因为终端里已 export 过该变量
  - 监听地址 `127.0.0.10` → `os.getenv('APP_HOST','0.0.0.0')`
  - CORS 白名单改为环境变量 `CORS_ORIGINS` 驱动，原本地地址保留为兜底
  - 日志级别 `DEBUG` → `INFO`（生产日志量会爆炸）
- **requirements.txt 补依赖**：pymysql、cryptography、pandas、numpy、openpyxl、httpx 都是代码里实际 import 但清单遗漏的；另加 gunicorn==21.2.0（systemd 要用）

### 新增部署产物（deploy/）
- `deploy/DEPLOY.md` —— 12 节完整手册（安全组 / RDS / 系统初始化 / 上传 / 配置 / 发布 / RBAC 初始化 / Nginx / 验收 11 项 / 报错对照 / 运维）
- `deploy/deploy.sh` —— 幂等一键发布：rsync → venv → 依赖 → 权限 → systemd → `/docs` 自检。`--exclude .env` 和 `src/config/config.yml` 保证重发布不会误删密钥
- `deploy/fastapi.service` —— `PYTHONPATH=/opt/fastapi:/opt/fastapi/src`
- `deploy/nginx-fastapi.conf` —— 反代 + `client_max_body_size 50m`（否则 Excel 上传 413）+ `proxy_read_timeout 300s`（否则 AI 接口 504）
- `deploy/config.yml.example`、`deploy/env.production.example`

### 环境结论
- AL3 默认只有 Python 3.6，官方源直接提供 3.11：`dnf install -y python3.11`
- 部署根目录约定 `/opt/fastapi`，运行用户 `fastapi`，Gunicorn 监听 `127.0.0.1:8090`
- 项目目录不是 git 仓库（无 `.git`），部署走 tar + scp 上传，不能用 git clone
